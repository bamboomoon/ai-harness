# Readable Code

以降低理解和修改代码所需的认知负荷为目标。根据行为契约和变化需求权衡设计；原则提供判断依据，
具体写法服从上下文，机械排版交给格式化工具。

## 职责与边界

- **高内聚、低耦合**：将共同维护状态与不变量的行为放在一起，以职责和变化原因判断组件边界。
- **信息隐藏、依赖倒置**：围绕需要独立变化的契约隔离实现细节；抽象带来的稳定性应超过引入间接层的理解成本。
- **契约式设计、信任边界**：在不可信输入进入系统时验证输入契约，由拥有相关状态的组件维护业务不变量；
  校验是否可复用取决于调用路径、状态变化和信任假设。
- **DRY**：为同一知识保留权威表达，以语义和变化原因判断复用价值，而非代码形状的相似程度。
- **YAGNI**：让代码和扩展点服务于已知需求，以真实使用关系判断保留价值；可达性分析应包含框架和动态入口。

## 表达与局部推理

- **逻辑分段**：通过恰当的空行体现代码的语义层次与职责边界，让紧密相关的操作保持连贯，让独立的逻辑步骤清晰区分。
- **局部推理**：按逻辑目的组织代码，让读者在有限上下文中理解数据流、求值顺序和失败来源；
  中间变量与方法提取应增加有意义的概念。
- **自顶向下阅读、抽象层级**：方法排列体现从高层意图到实现细节的展开，使相关调用形成连贯的阅读路径。
- **意图表达**：命名提供作用域内理解角色、用途和差异所需的信息；注释补充设计动机、约束和取舍。
- **最小惊讶原则**：让返回值、空值和副作用符合接口契约，并保持相邻接口的语义一致性。
- **封装、不可变性**：明确可变状态的所有权，限制共享可变状态，使输入转换和状态更新符合调用者可见的契约。
- **命令查询分离**：区分状态观察与状态改变，使副作用及其顺序可见；组合操作保留原子性和一致性要求。
- **声明式编程**：已有操作能够完整表达顺序、重复值和失败语义时，复用其语义；需要独立控制流时，显式表达控制流。

## 副作用、失败与验证

- **数据局部性、集合运算**：根据数据归属、一致性和执行成本选择处理位置。
- **错误透明性**：在具备恢复、翻译或隔离能力的边界处理失败，保留原因和诊断上下文，使故障与正常业务结果可区分。
- **资源管理、结构化并发**：将资源与任务的生命周期绑定到明确的作用域，保证失败路径上的清理，并保留适用的中断和取消语义。
- **行为保持重构**：以保持可观察行为为前提改善内部结构。
- **行为测试、封装**：围绕稳定接口验证可观察结果与副作用，减少测试对内部结构的依赖。
