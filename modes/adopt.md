# adopt：在已有项目中引入机制

输入：[discover](discover.md) 的现状报告。按阶段推进，每阶段结束汇报并经用户确认；计划与进度写入仓库内的过程文档（完成后归档），避免上下文丢失。
每个阶段先对照现状判断**是否需要、缺什么**，只补缺口；已有且有效的机制保留并沿用其工具与命名。

## 1. 基线（可选，推荐）

- 目标：用证据说明机制是否生效，而不是凭感觉。
- 做法：根据纠正案例设计 2~3 个会触发它们的任务，用能力较低的模型在隔离工作区各跑 1~2 次，保存 diff；能脚本判定的指标写成评分脚本。
- 何时不需要：用户只要求建立机制、不需要前后对比时，跳过并在报告中说明。
- 完成标准：基线结果与评分脚本，可在阶段 7 复用。

## 2. 静态检查（L0）

- 目标：每个模块一个 `check` 入口（格式、lint、类型、生成代码一致性），本地与 CI 同一条命令，工具版本锁在仓库内。
- 决策点：沿用项目已有的 lint 与格式化工具，只补缺失项；依赖方向能写成 lint 的写成 lint；Clean Code 护栏（复杂度、函数长度、重复）只约束生产代码，阈值作上限。候选工具见 [../reference/stacks/](../reference/stacks/)。
- 先修存量再开启门禁；存量过大时先按目录或规则分批开启，并记录剩余范围。
- 完成标准：各模块 `check` 通过，拿一个故意的违规验证会被拦下。

## 3. 可复现的测试环境与 CI

- 目标：任何人（包括 agent）一条命令就能跑通各层测试，结果不依赖共享环境或手工准备的数据；CI 用同一入口。
- 决策点：测试依赖若已由 Testcontainers、现有 compose 等可复现方式提供，沿用；若依赖共享库或手工数据，改为一次性环境（启动依赖 → 迁移 → 经真实入口写种子数据 → 执行 → 销毁）。无法使用容器时，选择内嵌/内存替身或专用测试库，并说明代价。浏览器端到端测试为消除平台渲染差异，可让浏览器运行在固定容器中。
- 用桩模拟数据库行为的单元测试，考虑改写为真实依赖的集成测试。
- 首次在新环境跑端到端测试时，失败先在基准分支对照，区分既有问题与本次引入。
- CI：每模块静态+单元 job、集成/端到端 job、末尾汇总 job（被取消时跳过）；固定运行器版本，保持无平台警告。
- 完成标准：本地一条命令跑通各层；CI 全绿。

## 4. 测试可信度工具

- 目标：发现被削弱的测试、没测到改动的测试、强度不够的测试（见 [../reference/verification.md](../reference/verification.md)）。
- 决策点：防篡改检查几乎总是值得；先红后绿需要能在基准版本上运行改动的测试；变异测试在单元测试已有一定规模时才有意义，先对改动行、只出报告。
- 完成标准：每个工具在已知正例与反例上判定正确（可用阶段 1 的基线工作区验证）。

## 5. agent hook 与交付关卡

- 目标：编辑后即时修正格式与可自动修复的问题；回合结束运行改动模块的检查与测试可信度检查；交付前运行较慢的集成与端到端验证并留下与改动绑定的标记。
- 决策点：只为用户实际使用的 agent 配置 hook；各 agent 的协议与坑见 reference。慢的检查放交付关卡而不是每个回合。
- 完成标准：用模拟输入与一次真实会话各验证一次触发与退回。

## 6. 代码风格与示范清理

- 目标：复制 [../readable/](../readable/) 基线，把纠正案例与散落在 AGENTS、skill 中的项目规则收进各模块 `CONVENTIONS.md`（见 [../reference/style.md](../reference/style.md)）；项目已有 readable 类 skill 时，通用部分对照基线、项目部分移入 CONVENTIONS，能 lint 的进 lint；清理会被模仿的坏样例。
- 做法：清理交给能力较低的模型只依据风格指南与 AGENTS 执行，审 diff 并独立复跑交付关卡——既清理代码，也检验规则是否写清。
- 完成标准：规则、示范代码与 lint 三者一致；`.agents/skills/readable-*` 不含本仓库路径。

## 7. 规则与文档

- 按 [../reference/docs.md](../reference/docs.md) 重写根与模块 AGENTS（含必读 CONVENTIONS 提示、纠正落点表，以及按 discover 中用户确认的清单写的工具表），拆分端到端测试的运行文档与编写指南，归档过程文档。
- 完成标准：每个 AGENTS 只剩路由、推断不出的规则与验证入口；链接检查通过。

## 8. 对照实验

- 用阶段 1 的任务，以能触发 hook 的独立会话重跑并逐项对比；未生效的规则回到对应层修改；对规则做删除测试剔除 no-op。
- 完成标准：前后对比表，列出生效、未生效与已删除的规则。
