# adopt：在已有项目中引入机制

按阶段推进，每阶段结束汇报并经用户确认再进入下一阶段；计划与进度写入仓库内的过程文档（完成后归档），避免上下文丢失。

## 0. 盘点与基线

- 识别模块：按 `package.json` / `go.mod` / `pom.xml` 等 manifest 列出模块、技术栈与现有的 lint、测试、CI、hook、AGENTS、文档。
- 收集用户最近对 agent 的纠正（2~3 个真实例子），它们是后续所有规则的输入。
- 设计 2~3 个会触发这些纠正的任务，用低一级模型在隔离 worktree 中各跑 1~2 次，保存 diff，能脚本判定的指标写成评分脚本。
完成标准：一份现状清单（模块 × 已有机制）、纠正案例清单、基线实验结果。

## 1. L0 静态检查

- 每个模块一个 `check` 入口（格式、lint、类型）；工具版本锁定在仓库内，不依赖全局安装。
- 依赖方向写成 lint（Go depguard、TS 边界规则、Java ArchUnit）；代码生成加一致性检查；Clean Code 护栏（认知复杂度、函数长度、重复）只约束生产代码，阈值作上限。
- 按技术栈的具体配置见 [../reference/stacks/](../reference/stacks/)。先修存量再开启门禁。
完成标准：所有模块 `check` 通过，且拿一个故意的违规验证会被拦下。

## 2. 临时测试环境与 CI

- 用一个脚本启动一次性依赖（数据库、缓存、浏览器容器），迁移并通过真实入口写入种子数据，执行命令后销毁；本地与 CI 共用同一入口。
- 桩实现数据库行为的单元测试改写为 L2 集成测试；E2E 改连临时环境，去掉对共享开发库与预置账号的依赖；浏览器统一在 Linux 容器中渲染，视觉意图写成 `toHaveCSS` 等明确断言，不做截图比对。
- CI 每个模块一个 L0+L1 job，L2/L3 job 复用临时环境脚本，末尾一个汇总 job（`!cancelled()`）；固定运行器版本，使用当前大版本的官方 action。
- 首次在临时环境运行 E2E 时，既有失败要在基准分支上对照，区分既有问题与本次引入。
完成标准：本地一条命令跑通各层，CI 全绿且无平台警告。

## 3. 验证工具

防篡改检查、先红后绿证明、改动行变异测试（见 [../reference/verification.md](../reference/verification.md)）；三者先用基线实验的 worktree 验证判定正确，再接入 CI。
完成标准：每个工具在已知正例与反例上判定正确。

## 4. hook 与交付关卡

编辑后单文件格式化与自动修复；回合结束运行改动模块检查与测试可信度检查（同一组待审项只退回一次）；交付关卡脚本与 Stop hook 指纹比对；Claude Code 与 Codex 各一份配置共用脚本。
完成标准：用模拟输入与一次真实会话各验证一次触发与退回。

## 5. 代码风格与示范清理

把纠正案例写成项目级 readable（见 [../reference/style.md](../reference/style.md)）；必守项进模块 AGENTS 或 lint。清理会被模仿的坏样例时，交给低一级模型只依据 readable 与 AGENTS 执行，审 diff、独立复跑交付关卡——既清理代码，也检验规则是否写清。
完成标准：规则、示范代码与 lint 三者一致，没有「规则写一套、代码是另一套」。

## 6. 规则与文档

按 [../reference/docs.md](../reference/docs.md) 重排根与模块 AGENTS（何时 | 读、纠正回路、测试规则），拆分 E2E 的运行文档与编写指南，归档过程文档。
完成标准：每个 AGENTS 只剩路由、推断不出的规则与验证入口；链接检查通过。

## 7. 对照实验

用阶段 0 的同一组任务，以独立会话（能触发 hook）重跑，逐项对比；未生效的规则回到对应层修改，对规则做删除测试剔除 no-op。
完成标准：一份前后对比表，列出生效、未生效与已删除的规则。
