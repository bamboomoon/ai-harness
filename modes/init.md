# init：为新项目铺好机制

新项目没有存量，一次铺好，之后每条纠正走 [correct](correct.md)。

1. **确认模块与技术栈**：每个模块的目录、manifest、技术栈、运行方式；问用户最在意的 2~3 条代码风格偏好。
   完成标准：模块清单与偏好清单。
2. **L0 检查**：按 [../reference/stacks/](../reference/stacks/) 为每个模块配置格式、lint（含依赖方向与 Clean Code 护栏）、类型检查，并提供单一 `check` 入口。
   完成标准：空项目上 `check` 通过，故意的违规被拦下。
3. **测试骨架**：每层放一个最小示例——L1 单元测试、L2 用临时环境脚本的集成测试、L3 E2E（Web 项目含浏览器容器）。
   完成标准：各层示例在本地一条命令通过。
4. **验证工具、hook、交付关卡、CI**：从 [../templates/](../templates/README.md) 复制并按模块调整。
   完成标准：hook 用模拟输入验证一次；CI 首次运行全绿。
5. **规则与风格**：写根与模块 AGENTS（何时 | 读、纠正回路、测试规则、必守规则），为每种语言建项目级 readable（核心原则 + 主题文件，先用偏好清单填充）；加 PR 模板。
   完成标准：AGENTS 与 readable 链接检查通过，每条规则都有正例。
