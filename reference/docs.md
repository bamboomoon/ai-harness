# AGENTS.md 与文档

## AGENTS.md 写法

- 读者是 agent。每一行在每个回合都占上下文，只写**推断不出**的内容：约定、理由、坑。
- 文档引用写成「何时 | 读」表：首列是触发条件（agent 按手头任务匹配），一行一个分支；同义改写合并为一行。
- 删 no-op：模型默认就会遵守的话（泛泛的 Clean Code、Clean Architecture 转述）。原则放进 readable 的引导词，依赖方向放进 lint。
- 删环境缓存：`package.json` 脚本清单、配置文件内容、目录列表——agent 自己查得到，写在文档里只会过时。
- 正向表述目标行为；禁止句只用于无法正向表述的硬护栏，并配上应该怎么做。
- 进入子目录时 Claude Code 与 Codex 都会加载该目录的 AGENTS.md/CLAUDE.md，根文件不必逐一路由到模块，只保留「跨多个模块」一行。
- 必守规则写进模块 AGENTS 或 lint，不依赖「先加载某个 skill」——实验中约一半的 agent 没有加载 skill；引用 skill 时给仓库相对路径，并注明 Skill 工具不可用时直接读文件。
- `CLAUDE.md` 用软链接指向 `AGENTS.md`，两种工具读同一份。

根 AGENTS 建议包含：一句话模块地图、何时 | 读、纠正回路、测试层级与三条测试规则（最低可观察层、修 bug 先红、存储交给 L2）、hook 与交付关卡、交付说明（指向 PR 模板）、少量约定。

## 文档分工（按寿命，而不是按类型）

| 类别 | 放哪里 | 怎么维护 |
| --- | --- | --- |
| 现行事实（术语、架构、对外契约） | `CONTEXT.md`、README 架构节、模块 `docs/`（仅对外有契约的模块） | 与代码同一个 PR 修改 |
| 决策 | `docs/adr/` | 只追加，被推翻时标记 superseded |
| 过程产物（需求、调研、迁移方案、bug 调查、一次性验证记录） | Issue / PR；结束后 `docs/archive/` | 事实沉淀到代码、测试与现行文档后归档 |

- 需求放 Issue，验收条目用 Given/When/Then，最终落成 E2E。
- 不建 bug 文档目录：bug 进 Issue，修复附回归测试；暴露的坑走纠正回路。
- 一篇文档开头需要写「本文状态……以某某为准」，说明它是过程产物，应该归档。
- 链接检查纳入 CI（跳过围栏代码、行内代码与归档目录；本机绝对路径视为错误）。

## E2E 文档

每个有 E2E 的模块两份：`README.md`（运行、证据位置、连接其他环境）与 `WRITING.md`（给 agent 的编写步骤，每步带完成标准）：
是否需要 E2E → 从验收条目与设计清单推导用例（每个约束、业务分支、落库结果都有对应用例）→ 复用现有 helper 与临时环境账号 → 断言与稳定性约定 → 运行到通过并说明测试改动。覆盖范围以测试标题与标签为准，不在文档里复述场景细节。
