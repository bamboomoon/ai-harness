# 验证体系

每个机制给出目标、决策点与一个例子；命令、路径与工具以 discover 的结果为准。

## 测试层级

| 层 | 目标 | 典型依赖 | 建议触发 |
| --- | --- | --- | --- |
| L0 | 格式、lint、类型、生成代码一致性 | 无 | 编辑后、回合结束、CI |
| L1 | 纯逻辑与「写入前拒绝」的校验 | 无 IO | 回合结束、CI |
| L2 | 单模块 × 真实依赖（数据库、缓存、消息、进程 stdio） | 可复现的测试环境 | 交付关卡、CI |
| L3 | 用户入口的端到端旅程 | 同上 + 浏览器或客户端 | 交付关卡（smoke + 受影响领域）、CI（全量） |
| L4 | 真实外部服务（模型、云资源） | 凭据 | 显式触发，手动 |

规则：行为变更在能观察到它的最低一层补测试；修 bug 先写在旧实现上失败的测试；读写存储的行为交给 L2，而不是手写数据库行桩。项目没有某一层的需求就不建。

## 可复现的测试环境

- 目标：测试不依赖共享环境或手工数据；本地与 CI 同一入口；结束后不留痕迹。
- 决策点：已有 Testcontainers、compose、devcontainer 等可复现方式时沿用；否则用一个脚本完成「启动依赖（独立命名、随机端口、易失存储）→ 迁移 → 经真实入口写种子数据 → 导出连接与凭据 → 执行命令 → 销毁」。已导出的环境变量应优先于项目的本地配置，确保测试连不到开发环境。
- 浏览器端到端：不同系统的字体渲染不同，布局类断言会随平台变化；可让浏览器运行在固定的容器中，测试进程通过远程连接驱动它。视觉意图写成样式与尺寸的明确断言；截图比对在界面频繁变化时几乎只报基线过期，只在界面稳定、需要守护设计系统时考虑。
- 例：compose 启动 PostgreSQL/Redis（tmpfs、随机端口），迁移后经管理接口创建普通账号；Playwright 官方镜像运行 `playwright run-server`，测试经 `PW_TEST_CONNECT_WS_ENDPOINT` 与 `PW_TEST_CONNECT_EXPOSE_NETWORK='<loopback>'` 连接。

## 测试可信度工具

均只出报告：agent 先处理（补测试、删除意外的跳过）或按组说明，人审说明并决定是否接受删除测试、抽查等价变异。

- **防篡改检查**：对比基准，标记删除的测试文件或用例、新增跳过/聚焦标记、断言数量减少、快照或 golden 文件变更。按项目语言补全跳过、断言与测试名的写法模式。
- **先红后绿**：把改动的单元测试放到基准版本的工作区运行应失败、在当前版本运行应通过。粒度能到测试函数就到函数，否则按文件；「旧实现上也通过」标记待审（重构或补覆盖属正常）。
- **改动行变异测试**：由 diff 求改动行，只统计落在其上的变异；存活或未覆盖逐条补测试或说明为等价变异。按语言选工具，见 stacks。单元测试尚少时价值有限，可暂缓。

## agent hook

- **编辑后**：只处理被编辑的文件（格式化、自动修复、可自动归位的顺序问题），修不掉的问题立即交回 agent；目标数秒内完成，整包检查留给回合结束。
- **编辑前（可选）**：编辑模块代码前扫描会话记录（hook 输入的 `transcript_path`）中的工具调用参数，确认读过该模块 `CONVENTIONS.md`，没读则以退出码 2 + stderr 拒绝（两种 agent 通用）。只认工具调用、不认正文提及与写入内容；文档文件与没有 CONVENTIONS 的目录不拦；拿不到会话记录时放行。何时需要：必守规则放在 CONVENTIONS、且观察到 agent 跳过必读提示时。
- **回合结束**：对有改动的模块运行 check 与单元测试，失败即退回；再跑测试可信度检查，新的待审项退回一次，按内容指纹去重，避免阶段性汇报的回合被反复阻塞；已因 hook 继续过一轮时改为提示，避免死循环。
- **交付关卡**：一个脚本对受影响模块运行 L2/L3 与改动行变异测试，都不跑全量：L2 只跑改动的包及依赖它们的包（改了迁移等非代码文件时全量），变异只作用于改动文件（工具默认变异整个包时显式排除其余文件），L3 只跑 smoke 与 agent 传入的领域标签（各模块用同名标签，如 Ginkgo label 与 Playwright tag），全量留给 CI；通过后把改动指纹写入仓库本地状态；回合结束发现有模块代码改动而指纹不符时退回一次，要求运行关卡或声明「未交付」。
- 协议要点：Claude Code 与 Codex 都接受 `{"decision":"block","reason":...}`；被编辑文件的路径分别来自 `tool_input.file_path` 与 `apply_patch` 补丁头；仓库根优先取会话项目根（Claude Code 的 `CLAUDE_PROJECT_DIR`），其次 hook 输入的 `cwd`；编辑后 hook 按文件所在目录定位仓库。其他 agent 按其 hook 协议适配，没有 hook 能力的 agent 靠 AGENTS 中的交付要求与 CI。

## CI

与本地同一套入口：每模块 L0+L1、L2/L3 复用测试环境入口、测试可信度 job（完整历史，基准为与主分支的合并基点）、文档与 CI 配置检查、末尾汇总 job（被取消时跳过，按层输出结果表）。测试日志中的关键数字写入运行总结；固定运行器版本、使用当前大版本的官方组件，保持无平台警告。例（GitHub Actions）：`$GITHUB_STEP_SUMMARY`、`if: ${{ !cancelled() }}`、`defaults.run.shell: bash` 以启用 pipefail。
